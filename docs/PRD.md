# Promptary 产品需求文档

> 版本 v1.0 · 最后更新 2026-09-11
> 这份文档用来防止开发过程中偏离主线。有分歧时以本文档为准;要改主线,先改这里。

## 一、一句话定位

浏览器里的 AI 生图提示词收集器:**看到好图,右键反推成提示词,分类存好,随时复用。**

## 二、目标用户

**核心用户:用文生图工具创作的人**(Stable Diffusion / Midjourney / 即梦 / 可灵 / NovelAI)。

他们的日常特征:

- 经常在网上刷图找参考(花瓣、Pinterest、X、Pixiv、小红书、Civitai)
- 看到喜欢的图,想知道「这图怎么生成的」,但拿不到原作者的提示词
- 收集的参考图散落在收藏夹、下载文件夹、微信截图里,真要用的时候找不到
- 需要中英双语 —— 国产工具吃中文,MJ / SD 吃英文

**明确排除的用户:**

- 纯 LLM 提示词工程师 —— 他们不需要图片反推
- 需要团队共享素材库的团队 —— V1 定位是个人工具

## 三、核心场景

| # | 场景 | 期望路径 |
| --- | --- | --- |
| 1 | 刷到喜欢的图,想留下它的「配方」 | 右键 → 反推 → 确认 → 入库(4 步以内) |
| 2 | 想复现某种风格,找自己存过的参考 | 搜「赛博朋克」→ 出结果 → 复制 |
| 3 | 看到别人分享的提示词文本 | 选中 → 右键 → 收藏(自动打标签) |
| 4 | 在生图工具页面,要用库里某条提示词 | 打开详情 → 一键注入输入框 |

**场景 1 是全产品的命脉。** 从「看到图」到「存下来」每多一步,坚持使用的概率就掉一截。

## 四、价值主张

| 现有做法 | 问题 |
| --- | --- |
| 浏览器收藏夹 / 下载文件夹 | 只能存图存不了提示词,无法按风格检索 |
| 手动复制到 Notion / 飞书 | 从看到图到存下来要 5 步以上,坚持不下来 |
| 在线提示词站 | 那是别人的库不是你的;而且要先把图传到别人服务器 |

**差异点:右键一步到位 + 提示词结构化 + 数据在本地。**

## 五、功能范围

### V1 — 核心闭环

- 右键反推图片提示词
- 右键收藏图片 / 收藏网页选中文字
- 图片悬停快捷按钮,快捷键 `Alt+Shift+P`
- 结构化反推(十个字段,见下)
- 反推结果预览后再入库
- 分类树 + 标签体系,反推标签自动创建
- 全文搜索(标题 / 提示词 / 标签 / 备注 / 来源)
- 详情编辑(标题、分类、标签、备注)
- 提示词注入生图工具页面
- BYOK 模型配置 + 连通性测试
- 存储位置透明化:实际路径、占用空间、条目统计可查
- 导入 / 导出备份(单文件 JSON,或导出到指定文件夹)

V1 已全部完成,下一阶段见 V1.5。

### V1.5 — 提效

- 提示词片段与组合器
- 翻译 / 扩写 / 精简
- SD ↔ MJ ↔ NAI 权重语法互转
- 以图搜图溯源(SauceNAO / ascii2d / Google Lens)
- 与 Obsidian / 本地文件同步

### V2 — 商业化

- 云同步(收费项)
- 默认 API 额度(拉新用,注意这不是成本问题而是防刷问题)

### 明确不做

| 不做 | 原因 |
| --- | --- |
| **插件内生图** | MV3 的 Service Worker 会被随时终止,而生图要 10~60 秒;叠加模型接入、失败重试与内容审核,投入产出比极低。改做「注入到已有生图工具」,更轻且体验更顺。 |
| **社区 / 提示词广场** | 需要内容审核与持续运营,那是另一个产品。 |
| **团队协作 / 共享素材库** | V1 定位个人工具。 |
| **自建提示词数据库** | 那是别人的库。本产品的价值在于「你自己的收藏」。 |
| **实时镜像到指定文件夹** | 技术上可行(File System Access API),但 Chrome 对目录的读写授权会在浏览器重启后失效,做不到无感,反而变成持续打扰。手动导出已经覆盖了备份、迁移、数据自主这三件事。 |
| **自定义 IndexedDB 存储位置** | 浏览器不提供此能力,扩展无权更改。这是 Chrome 的安全边界,不是实现取舍。 |

## 六、关键产品决策

这几条是已经拍板的,后续开发不要反复动摇:

1. **只支持 OpenAI 兼容协议。** DeepSeek / OpenAI / OpenRouter / 硅基流动 / 各类中转全部兼容。用户换服务商只需改 baseUrl + model,我们不为任何厂商写专属适配器。
2. **按目标模型区分反推规则 —— 这是产品最核心的差异化。** 同一个画面,Stable Diffusion 要逗号标签串 + 权重 + 画质词,FLUX 要完整句子且**加画质词反而有害**(CFG-distilled 模型不吃这套),Midjourney 要简洁描述加尾部参数,Seedream 用中文最顺。不做区分的「图片转提示词」,产出的东西必然有一半是废的 —— 用户拿到手还得自己重写一遍,那这个插件就没有存在价值。
3. **输出一条成品提示词 + 标签,不拆成散字段。** 用户要的是能直接粘进去出图的东西。拆开只会增加拼装负担,而且不同模型需要的排列顺序本来就不同,拆开反而写不对。标签保留是因为它服务于归档检索,和「能不能直接出图」无关。
3. **图片优先 URL 直传,失败降级 base64。** 让模型服务端自己去取图,省流量且避开本地跨域;防盗链站点再走本地下载。这条降级路径是必需的。
4. **反推结果预览后再入库。** 模型有幻觉,不确认就写库会污染用户收藏。让用户看一眼,成本极低但能挡掉大部分脏数据。
5. **数据本地优先且可导出。** 用户存的是自己的资产。不能导出,用户就不敢往里面存东西 —— 这是这类工具的死穴。
6. **设置与业务数据分离存储。** API Key 在 `chrome.storage.local`,收藏内容在 IndexedDB。好处是导出备份天然不会带出密钥。

### 模型档案:核心差异化的落地形式

定义在 `lib/vision/models.ts`。每个档案包含:格式规则(逐条写进 system prompt)、few-shot 示例、输出语言、是否需要负向词 / 画质词 / 参数后缀。

system prompt **按选中档案动态拼装**,不是写死的 —— 换模型就换一整套规则和示例。

| 档案 | 分组 | 提示词形态要点 |
| --- | --- | --- |
| Stable Diffusion | 标签系 | 逗号标签串,按「主体→外观→动作→服装→环境→构图→光线→画质」排;权重语法 `(x:1.2)`;必须带画质词;需要负向词 |
| FLUX | 自然语言系 | 完整连贯的句子;**不能加画质词**,无效且会把画面带偏;无负向词 |
| Midjourney | 参数系 | 简洁短语,末尾附 `--ar 3:2 --style raw --v 6.1`;需排除元素时用 `--no` |
| GPT-Image | 自然语言系 | 详细段落,当 brief 写;能吃很长描述;无参数无画质词 |
| nano banana | 自然语言系 | 描述式自然语言;画面中的文字要原样写出并说明位置 |
| Seedream | 中文系 | 中文描述,符合中文语序;无参数无画质词 |

**加新模型只需要往 `MODEL_PROFILES` 数组里加一项,不用改任何逻辑。**

收藏项会记下 `targetModel`,所以日后能按「这条是给哪个模型写的」来筛选。

## 七、数据与隐私

- 图片与提示词只存本机 IndexedDB,**不上传任何服务器**
- API Key 单独存放,导出备份时不会被带出
- 唯一的出网请求:调用用户自己配置的模型 API
- 无埋点、无遥测、无账号体系

这条是产品承诺,不是临时状态。V2 做云同步时,必须是用户显式开启的选项,不能默认上传。

## 八、成功指标

单用户工具没有 DAU 可看,用这些:

| 阶段 | 指标 |
| --- | --- |
| V1 | 自己连续使用 30 天不卸载;库内收藏 > 100 条 |
| V1.5 | 单条收藏的平均复用次数(打开详情 / 复制 / 注入)> 1 |
| V2 | 云同步付费转化率 |

判断 V1 是否成功的核心问题:**「看到图 → 存下来」这一步,我是不是真的用得下去?**

## 九、风险

| 风险 | 应对 |
| --- | --- |
| 模型 JSON 输出不稳定 | 已有容错解析(剥代码块、抓括号、字段类型兜底)与整句拼接降级 |
| DeepSeek 视觉模型是 `Exp` 实验版,可能变更 | provider 层可插拔,随时换；已在设置页提供多个预设 |
| 防盗链站点取不到图 | 三级降级:URL 直传 → 后台下载 → (待做)画布兜底 |
| Chrome Web Store 审核 | `host_permissions: <all_urls>` 是大权限,商店页面必须清楚说明用途(抓取用户右键指定的图片、向用户指定的页面注入提示词) |
| 权限冗余引发审核质疑 | 遵循最小权限,未使用的权限一律不申请 |
